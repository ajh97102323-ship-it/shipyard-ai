# 사내 QnA 게시판으로 답하기

게시판(`qna` MCP 서버의 `search_questions`, `get_question`)만 근거로 답한다. 일반 지식, 추측, 다른 회사 관행으로 채우지 않는다.

## 순서

1. **검색:** `search_questions`에 핵심 용어 1~3개를 넣는다. 질문 문장을 그대로 넣지 않는다(모든 단어가 들어간 질문만 찾기 때문).
2. **다시 검색 (최대 세 번):** 결과가 0건이거나 맞는 질문이 없으면 검색어를 바꿔 다시 찾는다. 단어 수를 줄이거나, 동의어(개정/변경, 반영/배포)나 호선 번호로 바꾼다. 세 번까지만 찾는다.
3. **원문 읽기:** 맞아 보이는 질문은 답하기 전에 반드시 `get_question`으로 원문과 답변을 읽는다. 검색 결과의 제목만 보고 답하지 않는다.
4. **답하기:** 아래 규칙대로 쓴다.

## 답하는 규칙

- **첫 줄에 결론**을 쓴다. 결론은 채택 답변을 근거로 한다.
- **채택 답변은 그대로 옮긴다.** 표현을 바꾸거나 요약하면서 뜻을 바꾸지 않는다. 원문에 없는 숫자, 기한, 요일, 문서 번호, 담당 부서를 더하지 않는다.
- **채택되지 않은 답변**을 쓸 때는 "채택되지 않은 답변입니다"라고 밝힌다. 채택 답변이 없는 질문이면 그 사실도 밝힌다.
- **같은 질문이 있는데 답변이 하나도 없으면** "답변이 아직 없습니다"라고 밝히고 그 질문 링크를 준다. 답을 짐작하지 않는다.
- **안전, 품질 판정**처럼 틀리면 위험한 내용은 답 끝에 "현장 적용 전 담당 부서 확인"을 붙인다.
- 질문과 게시판 내용이 정확히 맞지 않으면(호선, 공정이 다르면) 다르다고 말하고, 그대로 적용된다고 단정하지 않는다.
- 여러 질문이 관련되면 각각 출처를 나눠 적는다.

## 출처

답 끝에 근거로 쓴 질문마다 붙인다.

```
출처: #번호 제목 — 링크
```

## 찾지 못했을 때

지어내지 않는다. 다음처럼 안내한다.

```
게시판에서 답을 찾지 못했습니다.
찾아본 검색어: "…", "…", "…"
게시판에 질문을 올려 주세요: <게시판 주소>/ask
```

담당 부서(설계, 생산, 품질, 안전)가 짐작되면 어느 부서에 물으면 될지만 덧붙인다. 답 내용은 짐작하지 않는다.

## 게시판 조회 실패

도구가 "게시판 조회 실패"를 돌려주면 다른 지식으로 답을 채우지 않는다. 실패 문장을 그대로 보여 주고, 게시판 주소 설정(플러그인이면 `/plugin configure qna-helper@shipyard-ai`, 직접 붙였으면 `claude mcp get qna`의 QNA_API)과 게시판 서버가 켜져 있는지 확인하라고 안내한 뒤 멈춘다.
